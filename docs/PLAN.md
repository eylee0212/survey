# 10×10 삼목 계획서

## 목표

10×10 판에서 가로·세로·대각선으로 자기 돌 3개를 먼저 이으면 이기는 게임을 `index.html` 하나로 만든다. GitHub Pages(https://eylee0212.github.io/survey/)에서 바로 열린다.

## 조건(앞 프로젝트에서 이어 감)

- 외부 라이브러리·외부 글꼴·분석 도구를 쓰지 않는다. 코드와 스타일은 모두 `index.html` 안에 둔다.
- 게임 로직은 화면과 떼어 놓고 자동 시험을 붙인다.
- 저장소 맨 위의 빈 `.nojekyll`을 유지한다.
- 네트워크 요청·브라우저 저장소를 쓰지 않는다. 콘텐츠 보안 정책(CSP)으로 외부 연결을 막는다.

## 규칙

| 항목 | 규칙 |
|---|---|
| 판 | 10×10, 처음엔 비어 있다 |
| 차례 | 흑이 먼저, 흑·백이 번갈아 빈 칸에 돌 하나 |
| 승리 | 가로·세로·두 대각선 중 한 방향으로 자기 돌이 연속 3개 이상 |
| 무승부 | 승자 없이 100칸이 다 차면 |
| 끝난 뒤 | 더 둘 수 없다. "새 게임"으로 다시 시작 |

### 요청에 없어서 정한 것

- **4개 이상**: 연속 3개 이상이면 이긴다(4·5개로 이어져도 승리).
- **상대**: "두 사람(한 기기)"과 "컴퓨터"를 고를 수 있다. 컴퓨터 상대일 때 사람은 흑(선)이고, 바꿀 수 있게 "컴퓨터가 먼저" 선택지를 둔다. 기본값은 두 사람.
- **무르기**: 한 수 무르기를 둔다. 컴퓨터 상대일 때는 사람이 다시 둘 차례가 되도록 컴퓨터 수까지 함께 무른다.
- **승리 표시**: 이긴 돌 3개(이상) 줄을 강조한다.
- **컴퓨터 수 고르기**(결정적, 같은 판이면 같은 수):
  1. 바로 이기는 칸
  2. 상대가 바로 이기는 칸 막기
  3. 두면 이기는 칸이 두 곳 이상 생기는 칸(양쪽 위협)
  4. 상대의 양쪽 위협 칸 막기
  5. 그 밖에는 점수로: 내가 만드는 위협 수, 상대 위협 막기, 주변 돌 수, 판 가운데와의 거리 순. 동점이면 위쪽·왼쪽 칸.
  - 10×10 삼목은 선수가 매우 유리해서 먼저 두는 쪽이 제대로 두면 대개 이긴다. 컴퓨터는 "실수를 놓치지 않고 뻔한 수는 막는" 정도를 목표로 한다.

## 구조

- `index.html`
  - `<script id="game-core">`: 화면을 모르는 순수 함수. `GameCore` 하나로 내보낸다.
    - `createGame()`, `play(state, row, col)`(새 상태를 돌려줌, 원래 상태는 바꾸지 않음), `undo(state)`, `findWin(board, row, col)`, `chooseMove(state)`
  - `<script id="game-ui">`: 판을 버튼 100개로 그리고, 클릭·키보드(방향키·Enter/Space)로 둔다. 화면 낭독기용으로 각 칸에 "3행 5열, 빈 칸" 같은 이름을 붙이고 차례·결과를 알린다.
- `tests/load-core.js`: `index.html`에서 core 블록을 꺼내 `vm`으로 실행.
- `tests/core.test.js`: 규칙·승리 판정·무승부·무르기·컴퓨터 수.
- `tests/page.test.js`: 외부 참조·네트워크/저장 API 없음, CSP, `.nojekyll`.
- `tests/browser.test.js`: Playwright로 실제 클릭해 승리·컴퓨터 대전 확인(없으면 건너뜀).
- `package.json`: `npm test` → `node --test`. 의존성 없음.
- `.github/workflows/test.yml`: 푸시·PR마다 `npm test`.
